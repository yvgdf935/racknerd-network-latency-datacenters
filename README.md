## 三网实测：同一个商家，不同机房能差一倍

RackNerd 全球 20 多个机房，国内用户实际会用的就五六个。同一个运营商在不同机房的表现差得很远，所以“RackNerd 三网怎么样”这个问题只能分机房回答。

### 电信：圣何塞和西雅图最干净，DC-02 白天和晚上是两台机器

**圣何塞**是电信用户的第一选择。去程直连圣何塞，回程从圣何塞直入中国，也有测评记录到回程走 AS4134 回广州方向，延迟约 160ms，中途没有明显绕路。

**西雅图**三网双程直连，国际段走 Cogent 或 Telia，国内段对接各家骨干网。电信走 163 骨干，延迟 145–180ms，是三网里最稳的一条。

**洛杉矶 DC-02** 去程 163 骨干网直连，回程走 AS4134 国际出口。235 个国内节点实测平均约 197ms，最快的上海电信节点 135.7ms；白天延迟 150ms 出头，下午开始轻微丢包，晚高峰部分节点丢包 10% 以上，个别节点能飙到 500ms 以上。它也是被提到最多的“白天飞起、晚上卡成 PPT”的典型。

**洛杉矶 DC-03** 去程直连电信美西节点，接 twelve99 进机房；回程走 Cogent 出海，绕圣何塞或圣克拉拉回国。纯国际线路，没有 AS4134 直连，晚高峰体感一般。

**达拉斯**三网往返直连，200ms 上下。**芝加哥**的去程稍有绕路，有来源给到约 240ms，也有来源说在 200ms 以内，口径不一致，下单前自己 ping 一遍更靠谱。

### 联通：DC-02 最省心，DC-03 必须先测

**洛杉矶 DC-02** 是联通的主场。双向 AS4837 优化线路，平均延迟 190ms 左右，丢包几乎为零，几个来源都把它评为 DC-02 最稳的一条线。

**圣何塞**同样走 AS4837，延迟整体偏低，表现稳定。南方联通用户优先考虑圣何塞，北方可以看洛杉矶。

**达拉斯**联通也走 AS4837，三网往返直连，不偏科。

**DC-03** 的回程走 Cogent 出海，联通在晚高峰的表现两份测评说法相反。一份 11 月 7 日 23 点的记录显示三网都有抖动，联通最严重，广东联通节点代理速度掉到约 156Kbps；另一份测评说联通、移动基本零丢包。两边都同意的部分只有一句：联通用户选 DC-03 之前，务必自己补一个晚高峰测试。

**西雅图**国际段走 Cogent 或 Telia，没有针对国内的优化，联通表现中规中矩。

### 移动：三网里最看运气，达拉斯反而稳

**洛杉矶 DC-02** 移动去程走香港 CMI，回程 CMI 混合路由，延迟 200ms 上下，但有 20% 以上的波动，时好时坏。也有人说“还可以”，差别在于测试时段。

**圣何塞**移动 200–220ms，经过的中转节点比电信联通多，延迟高一截，好处是波动比 DC-02 小。

**达拉斯**移动往返直连，稳定性不错。移动宽带用户想少折腾，这个机房比 DC-02 更合适。

**西雅图**移动在晚高峰丢包偏多，是几个主力机房里移动体验最不稳定的一档。**DC-03** 移动回程路由比电信联通稍好，但不构成选它的理由。

## 晚高峰：白天和晚上是两台机器

多份测评都指向同一个结论：白天基本感觉不到问题，SSH 敲命令的延迟可以接受；晚上 8 点以后丢包上升，偶尔 SSH 会卡顿。联通和移动在多数机房能保持接近零丢包，电信在晚高峰的轻微丢包是老问题，部分节点超过 10%。

四个主力机房各有一个具体的坑：DC-02 坑电信，晚高峰节点丢包 10% 以上；DC-03 坑联通，抖动最严重时广东联通代理速度掉到 156Kbps 级别；西雅图坑移动，晚高峰丢包偏多；圣何塞相对最均衡，移动延迟偏高但波动小。

期望值也要放对位置。4K 秒开别想，日常浏览、建站、轻量代理、跑点小服务完全够用。圈内管它叫“廉价机皇”，说的是性价比，不是性能。

## 别只看别人的数据：4 个主力机房的测试 IP 与自测流程

最省事的验证方式是自己 ping。下面这组测试 IP 和 Looking Glass 地址来自公开整理，直接用：

| 机房 | 测试 IPv4 | Looking Glass |
| --- | --- | --- |
| 洛杉矶 DC-02 | 204.13.154.3 | `lg-lax02.racknerd.com` |
| 洛杉矶 DC-03 | 107.174.51.158 | `lg-lax03.racknerd.com` |
| 圣何塞 | 192.210.207.88 | `lg-sj.racknerd.com` |

| 达拉斯 | 198.23.249.100 | `lg-dal.racknerd.com` |

四步走完，比看十篇测评都准：

1. 本地 `ping` 上面的 IPv4，看回程延迟和丢包。Windows 直接 `ping 204.13.154.3`，Mac/Linux 用 `ping` 或 `mtr`。
2. 打开对应 Looking Glass 页面，从机房方向对你的公网 IP 做 traceroute，看去程绕不绕。
3. 在 LG 域名后加 `/100MB.test` 下载测速文件，比如 `lg-lax02.racknerd.com/100MB.test`，测实际下载速度。
4. 晚上 8–10 点再补一轮同样的测试。白天的数据只能说明一半问题，DC-02 就是典型例子。

双向对比之后，哪个机房适合你的宽带，一目了然。
